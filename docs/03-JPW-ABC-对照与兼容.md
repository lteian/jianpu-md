# JPW-ABC 对照与兼容决策

> 对标文档：JP-Word 4.0 使用手册（<https://happyeo.gitbooks.io/jp-word-manual/>），
> 重点是第 6 章《JPW-ABC 记谱法》。JP-Word 是中文圈最完整的简谱排版软件，
> 它的 ABC 记谱法是**目前唯一有公开完整手册的简谱文本格式**。
>
> 本文回答一个问题：**jianpu-md 的语法，哪些照抄它、哪些故意不一样、为什么。**

---

## 0. 为什么要对标它

三个现实理由，不是崇敬权威：

1. **它是唯一有手册的**。简谱没有生效国标（《音乐简谱记谱规范》仍是征求意见稿），
   行业惯例散落在教材里。JPW-ABC 至少是「按一套规则实现过、且卖出去过」的格式。
2. **要能读别人写的谱**。`小通` 用 JPW-ABC 写二胡分谱、并且有自己的解析器
   （`score/jpw.py`）。我们的渲染器如果读不了 JPW-ABC，两个 agent 就等于各写各的。
3. **省掉重新发明**。倚音、技法、房子这些结构，JPW 已经踩过坑了。

---

## 1. 决策原则

| 原则 | 含义 |
|---|---|
| **超集不替换** | jianpu-md 保留自己的写法（`@dun`、`/`、`^{1 2}`），同时**接受** JPW-ABC 写法。旧谱不迁移。 |
| **语义对齐，字面不强求** | `{DunYin}` 和 `@dun` 落到同一张记号表、同一个符号 `▼`，但字面不必一致。 |
| **不实现排版微调** | JPW 的 `ControlOptions{C:…}`、`Attachments` 坐标系统是「所见即所得编辑器」的产物，我们是「文本 → 一次成版」，坐标不该出现。 |
| **增量优先给二胡** | JPW 对弓法没有原生语法（它靠 Attachments 手摆），这块我们自己做（`@la`/`@tui`/`@0`–`@4`…）。 |

---

## 2. 音符 token：七段结构对照

JPW-ABC 的音符由 7 段顺序拼成（手册 6.8 节），jianpu-md 采用同样的段序：

| # | JPW 段 | JPW 写法 | jianpu-md 写法 | 状态 |
|---|---|---|---|---|
| 1 | 弧线开始 | `((` 两个左括号 = 2 条弧 | `(`（本项目目前单弧） | 🟡 单弧 |
| 2 | 技法 | `{BoYin,YanYin}` | `@w` / `@=` / `{BoYin}` | ✅ 双写 |
| 3 | 倚音 | `{6,2}` | `^{6,2}` / `{6,2}` | ✅ 双写 |
| 4 | 音高 | `#4` `b7` `1'` `6,` | 同 | ✅ |
| 5 | 时值 | `_`（减时线条数） | `_` 或 `/` | ✅ 双写 |
| 6 | 控制选项 | `{C:6.86}` | 忽略 | ⛔ 不实现 |
| 7 | 弧线结束 | `)` | `)` | ✅ |

多声部/和弦 `[5,1b35]`：**暂不支持**（见 §5）。

## 3. 逐项对照

### ✅ 已对齐（v0.2 起可直接吃 JPW-ABC 写法）

| 要素 | JPW-ABC | jianpu-md | 备注 |
|---|---|---|---|
| 音级 | `1`–`7` / `0` / `X`(锣鼓经) | `1`–`7` / `0` / `x` | |
| 八度 | `'` 高、`,` 低，可叠 | 同 | |
| 变音 | **前置** `#4` `b7` | 前置（`4#` 后置也吃） | 兼容两种手写习惯 |
| 减时线 | `_` 条数 | `_` 或 `/` | |
| 增时线 | `-` 条数，可紧贴后续音 `5-3` | 同 | 兼容层已处理粘连 |
| 附点 | `_.` 或 `._` | 任意顺序 | 按出现次数统计，不按顺序 |
| 倚音 | `{6,2}` 前倚音（16 分） | `{6,2}` / `^{6,2}` | 后倚音 JPW 用特殊文字，我们用 `_{…}` |
| 技法 | `{DunYin}` `{BoYin}` `{YanYin}` | `{…}` / `@dun` / `@w` / `@=` / 中文 `{顿音}` | 见 §4 映射表 |
| 弧线（连弓） | `( … )`，可跨行、可多层 | `( … )`，可跨行 | 跨行配对已修 |
| 小节线 | `|` `||` `|]` `|:` `:|` | 同 | |
| 房子 | `|[1.` `|[2.` | 同 | v0.2 新增渲染 |
| 段落标记 | `$` / `$(True)` | `$`（选项忽略） | v0.2 新增 |
| 标准文字 | `"…"` | 同 | v0.2 新增，挂到下一个音 |
| 行内拍号 | `7/8` | 同 | v0.2 新增，拍数校验跟着变 |
| 歌词 | `.Words` 节，`/` 为跳跃符 | `L:` 行，空格/逐字 | 语义相近，载体不同 |

### 🟡 故意不同

| 要素 | JPW-ABC | jianpu-md | 为什么不同 |
|---|---|---|---|
| 文件结构 | `.Title` / `.Voice` / `.Words` 七个节 | YAML front matter + `%` 段落 + `L:` 行 | 我们要的是「Markdown 里能写、GitHub 上能看」，节名会污染正文 |
| 弧线语义 | 每个 `(` 是「从这个音出发的一条弧」 | `(` 标记弧起点、`)` 标记终点 | 我们的写法更像手写谱的视觉直觉；多层弧暂不需要 |
| 技法名 | 拼音（`DunYin`） | 短名（`dun`）+ 拼音别名 + 中文别名 | 手写谱时 `@dun` 少敲 4 个键；别名表兜住互操作 |
| 倚音时值 | 固定 16 分 | 可写 `^{1//}` 指定 | 二胡的装饰音时值差别很大（打音几乎不占时值） |
| 二胡弓法 | 无原生语法，靠 Attachments 手摆 | `@la` `@tui` `@0`–`@4` `@chuo` `@zhu` `@rou` `@o` `@nei` `@wai` | **这是我们的增量**，JPW 用户得手摆坐标 |
| 歌词载体 | 独立 `.Words` 节 + 对位坐标 | 紧跟乐谱行的 `L:` 行 | 文本里读谱时歌词就在眼前，不用跳节 |

### ⛔ 不实现（并说明理由）

| 要素 | 为什么不 |
|---|---|
| `ControlOptions` `{C:…}` | 全是排版微调（第几个音的宽度、行位置）。我们是自动排版，接受这些参数等于把排版权交回用户。 |
| `Attachments` 坐标系统 | `Text@38,1(1.00,-2.60)` 这种「第 38 小节第 1 个音，偏移 (1.0, -2.6)」是编辑器里鼠标拖出来的。写进 Markdown 就是灾难。 |
| `.Fonts` / `.Page` 节 | 字体和页面参数属于主题（`Theme`），不进谱面文本。 |
| 特殊房子/特殊弧线 | 同上，任意定位的符号不属于「文本可表达」的范畴。 |
| 多声部 `Branch` | 复杂度和收益不成比例，M2 之后再谈（真需要时先做「双声部对齐」而不是任意临时声部）。 |
| 锣鼓经 `X台` | 保持 `x` 占位，暂不做字符谱。 |

| JPW 拼音 | 中文 | 归一化 key | 符号 |
|---|---|---|---|
| `DunYin` | 顿音 | `dun` | ▼ |
| `BoYin` | 波音 | `w` | ⌣ |
| `YanYin` | 延音 | `=` | — |
| `ChanYin` / `DaYin` | 颤音 / 打音 | `tr` | tr |
| `FanYin` | 泛音 | `o` | ○ |
| `RouYin` | 揉弦 | `rou` | 吟 |
| `ChuoYin` / `ZhuYin` | 绰音 / 注音 | `chuo` / `zhu` | ↗ / ↘ |
| `LianYin` | 连音 | `lian` | ⌒ |
| `LaGong` / `TuiGong` | 拉弓 / 推弓 | `la` / `tui` | ㄇ / ∨ |
| `HuanQi` | 换气 | `v` | v |

查表顺序：原样 → 首字母小写 → 中文直查；查不到就保留原名并给 `未知记号` 告警（**不静默丢弃**）。
唯一的例外是 `=`：`YanYin` 和 `BaoChiYin` 共用同一个符号，这是乐理上的实情，不是 bug。

## 5. 尚未支持（路线图）

| 项 | 现状 | 计划 |
|---|---|---|
| 和弦 `[5,1b35]` | 解析器会把 `[` 当成三连音/房子 | M2：纵向堆叠 + 播放时同时发声 |
| 多层弧线 `((2)` | 只处理单层 | M2 |
| 后倚音 | `_{…}` 可用，但 JPW 用特殊文字实现，语义不完全等价 | 保持现状 |
| 连音弧（三连音） | 我们用 `3[1 2 3]`，JPW 用 `{(3}` | 两个都认（`{(3}` 待做） |
| 伴奏记号 `( )` | 未实现 | 优先级低（民乐分谱少用） |

## 6. 兼容层在哪、怎么工作

实现集中在 `src/parser.ts` 的 `preprocessJpw()`，三步，顺序不能换：

```
1. {C:6.86}      → 丢弃（排版微调）
2. {DunYin}      → " @DunYin "（两侧补空格：记号属于前一个音，不能和后音粘成一个 token）
3. {6,2}         → ^{6,2}（剩下的纯音高花括号才是倚音）
```

之后交给既有 tokenizer。几个必须记住的坑（都踩过）：

- **引号内空格**：`"渐慢 rit."` 里的空格要用 `\u0001` 占位，不能用 `\u00A0`——JS 的 `\s` 认 `\u00A0`，照样会被 split 撕开。
- **增时线粘连**：`5-3` 必须拆成 `5 - 3`，否则整个 token 解析失败、音符被静默丢弃。
- **独立记号 token**：兼容层拆出来的 `@DunYin` 是独立 token，归属规则是「小节内有前一个音就归它，小节开头归下一个音」——两种写法 JPW 手册里都有。
- **圆滑线跨行**：JPW 与实际手写谱都常把一条连弓拆在几行里，所以圆滑线配对必须**全曲**配对，不能一行一算。
