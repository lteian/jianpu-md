# 版心与间距：从出版谱反解出来的常数

`src/layout.ts` 里的版心/间距常数不是拍的，是从一份 A4@300dpi（2480×3508）的二胡
出版谱扫描件上逐音量的。这份文档记下反解方法和结论，改常数前先读。

素材：`generated/score-photos/erhu-raw.jpg`
二值化：`convert erhu-raw.jpg -colorspace Gray -threshold 55% -compress Zip pbm:page.pbm`
探针：`tools/scan2jp.py`（P4 读取 + 8-邻域连通块 + 几何判据字形识别）

## 版心

整页 11 行的墨迹左右界高度一致：

```
行1..10  ink x = 239 .. 2244   净宽 2005px   左边距 239  右边距 235
```

所以原谱版心是 **2005px 宽、左右等边距约 237px**。

换算到 794 单位的 viewBox（1 单位 = 3.1234px）后要注意一个坑：
**这里量的是墨迹，不是排版盒**。首音的墨迹左界 = 盒左沿 + PAD + 半个音宽 - 半个字宽。
所以 `marginL` 不能直接填 76，要减去"半个音宽 + PAD - 半个字宽"≈19 单位。

当前取值：`marginL = marginR = 62`，实测首音墨迹 250–262px（原谱 239，差 <1%）。

## 间距：没有固定项，纯时值比例

出版谱每行两端对齐，行内所有间距被同一个比例 s 拉伸，所以绝对间距不能直接拿去反解。
只有当**相邻两音的时值不同**时，差值才与 s 无关地给出模型：

```
相邻音左边界距离 = (M + d_i/2 + d_j/2) × s
```

取"不跨拍边界、不跨小节"的音对，用 `d(八分) - d(十六分)` 反解，四行独立算：

| 行 | M (px) | s (px/拍) |
|---|---|---|
| 系统1 | -1 | 232 |
| 系统2 | -1 | 192 |
| 系统3 | 0 | 220 |
| 系统10 | 0 | 232 |

**M ≈ 0**：没有固定最小占位，纯按时值比例排。这正是之前两版模型都错的地方——
`max(beats, 下限)` 让八分/十六分只差 1.13 倍，`26 + 120×beats` 又让八分偏窄。

`s` 各行不同（192–232）不是巧合，是两端对齐的拉伸比。

拍边界额外留白四行惊人一致：**0.130 / 0.130 / 0.130 / 0.129 slot**。

自然槽（未拉伸）由"5 小节那行刚好填满"反解：`642 单位 / 10 拍 ≈ 60 单位/拍`。
**但 `slot` 最终定的是 50**，理由见下——它其实是断行旋钮，不是间距旋钮。

每行都两端对齐时，行内字距只取决于 `版心宽 / 该行总拍数`，**与 `slot` 无关**：

```
w(16分) = 0.25 × 版心宽 / 该行总拍数
```

4 小节的一行（8 拍）→ 57px；5 小节的一行（10 拍）→ 47px。`slot` 一变，`scale`
随之反向变，乘积不变。所以 `slot` 唯一的作用是决定**一行放得下几个小节**。

原谱的小节数是按乐句定的（4/5/4/5/6/6/5/4/5/4/2），其中 6 小节 = 12 拍最密。
要让 12 拍挤进 670 单位：`slot × (12 + 0.78) + 12 × PAD <= 670` → `slot <= 50.2`。
取 50 后，整曲 11 行与原谱**逐行一致**、正好 1 页 A4。

```ts
slot = 50             // 断行旋钮：决定每行放得下几个小节
MIN_SLOT = 0          // 实测无固定项
BEAT_GAP_SLOT = 0.13  // 拍边界额外
PAD = 3.2             // 小节线两侧（原谱贴得很紧，各约 10px）
noteSize = 18.7       // 字高对齐到 45px（原谱 44–45px）
marginL = marginR = 62
```

## 两个容易再犯的错

1. **别用 `labeled` 的绝对 x 当版面坐标**——`read_system` 返回的是裁剪后相对坐标，
   只有"差值"（净宽、间距）可信。要看绝对边距，得从整页列投影重新量。
2. **别按"是不是最后一行"决定撑不撑满**。版心宽度微调就会让首行被误判，
   整行压到半页。现在的判据是"该行确实换过行 + scale > 1.6"，见 `layout.ts` 的 `wrap`/`isTail`。

## 转录工具的两个致命坑（已修，别再踩）

1. **坐标系统一**：`read_system` 返回的 blob 坐标是**裁剪后**的，`ytop/ybot` 是整页的。
   增时线的 y 过滤曾直接拿两者相比，条件恒假 → 增时线**从未被挂上过**。
   行 1–4、8–10 恰好没有增时线，所以一直没暴露。
2. **记号的归属不是"相邻"而是"落在两音之间"**：
   - 附点、增时线都**居中排在下一个拍位**，离字心 36–84px，用 `<=30px` 半径会全丢；
   - 八度点画在字的**正上/正下方**，是居中的，必须按最近字心归属，
     否则 `d.x0` 略小于字心会被判给前一个音，低八度记号整体错位。

补上之后又出现"多出来的拍"（2.25/2.5 拍），说明阈值放宽引入了误挂。
最终解法不是继续调几何阈值，而是**拿节拍算术当校验器**：某小节时值不为 2 拍时，
枚举该小节内可撤销的记号，取"撤销最少且刚好合 2 拍"的组合。
误挂必然破坏算术，而真记号撤销后算术就对不上——这一条把不平衡小节从 8 个降到 1 个。

（剩下的 1 个是系统 7 第 1 小节，间距证据自相矛盾，留待人工确认，不猜。）
