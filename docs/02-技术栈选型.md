# 技术栈选型（v1 建议）

## 一句话结论

**TypeScript 纯前端：自研"解析 → 排版 → SVG"三段式核心库 + React/Vite 外壳 + Web Audio 手写二胡合成器；
打包成 Tauri 桌面版；不引第三方乐谱渲染引擎。**

---

## 1. 为什么不用现成的渲染引擎

| 候选 | 为什么不行 |
|---|---|
| VexFlow / abcjs | 为五线谱设计，简谱的"数字 + 上下八度点 + 减时线 + 增时线"是**二维网格排版**，套进五线谱模型会处处打架 |
| OSMD 的 Jianpu 模式 | 必须先进 MusicXML，且是**闭源赞助版**；我们要的输入是纯文本 |
| LilyPond + jianpu-ly | 输出最漂亮，但要装 Python + LilyPond（≈200MB），出图是"编译"而不是"实时预览"，做不了"边打边看" |
| 直接嵌 `<canvas>` 画 | 放大糊、不能复制文字、打印稀烂。**打印级必须 SVG** |

自研的代价可控：`dolce/jpeditor` 已经证明一个人用 TS 自绘 SVG 能做出完整简谱编辑器。

## 2. 分层

```
┌──────────────────────────────────────────────┐
│ apps/desktop (Tauri)   apps/web (Vite)       │  ← 外壳，很薄
├──────────────────────────────────────────────┤
│ ui: React 18 + Tailwind + CodeMirror 6       │  ← 编辑器/工具栏/播放条
├──────────────────────────────────────────────┤
│ core (纯 TS，零 DOM 依赖，可 node 跑)         │
│   parser  文本 → AST                          │
│   layout  AST → 行/页/坐标（排版引擎）         │
│   render  AST+坐标 → SVG 场景树               │
│   play    AST → 事件时间轴 → Web Audio        │
│   export  → SVG / PNG / PDF / MIDI / MusicXML │
└──────────────────────────────────────────────┘
```

**关键约束：core 不许碰 DOM。** 这样同一份代码能跑在浏览器、node（批量出 PDF）、CI（谱面回归测试）。

## 3. 具体选型

| 层 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript 5.x，`strict: true` | 谱面 AST 类型多，类型就是文档 |
| 构建 | Vite 5 | 冷启动快；产出纯静态，NAS 上 nginx 一放就能用 |
| 框架 | React 18 + Zustand | 生态最大、招人/接手成本最低 |
| 源码编辑器 | CodeMirror 6 + 自定义 StreamLanguage | 比 Monaco 轻 10 倍，语法高亮/错误波浪线够用 |
| 谱面渲染 | **自研 SVG**（手写 scene graph） | 矢量、可选中、可打印、可 diff |
| 排版 | 自研单一 pass 的"测量 → 换行 → 两端对齐" | 简谱不需要五线谱那套 vertical spacing 算法 |
| 字体 | Noto Serif CJK 子集 + Times 数字，WOFF2 内嵌 | 打印一致性，避免用户机器没字体 |
| 播放 | Web Audio API 手写语音 | 已验证：锯齿波 + 颤音 + 低通，`peak 0.54 / rms 0.13`，接近二胡 |
| 高保真音色 | 可选加载 `.sf2`（spessasynth） | 想更真就挂二胡采样，不挂也能用 |
| 导出 PDF | 浏览器打印（`@page A4`）+ 服务端 `pdf-lib` 兜底 | 免装打印驱动 |
| 导出图片 | SVG → Canvas → PNG | |
| 导出 MIDI | `midi-writer-js` | 舞台/伴奏场景要 |
| 桌面壳 | **Tauri 2**（不是 Electron） | 安装包 3–8MB vs 120MB，NAS/老电脑友好 |
| 测试 | Vitest（core 单测）+ 谱面快照（SVG 字符串比对） | 排版改动必须能一眼看出 diff |
| 部署 | 纯静态 + 可选 PWA | 断网也能用，符合"娃练琴"场景 |

## 4. 里程碑

| 阶段 | 内容 | 验收 |
|---|---|---|
| M0（已完成） | 单文件 HTML 原型：解析 + SVG 排版 + 二胡播放 | 渲染 A4 一页小星星，无告警，音频有波形 |
| M1 | 把原型拆成 `core` 包 + React 外壳，补三连音/倚音/房子/多声部 | 能排一首真实二胡曲（如《赛马》片段） |
| M2 | 导出 SVG/PNG/PDF/MIDI；`.md` 文件打开/保存 | 打印出来像出版物 |
| M3 | 二胡专属增强：指法推荐、把位图、弓法自动分配（连弓/分弓） | 这是别人没有的 |
| M4 | Tauri 桌面版 + PWA | 双击即用 |

## 5. 风险

1. **排版是深坑**：两端对齐、连音线跨行、歌词避让，工作量通常被低估 3 倍。对策：先做"能看"，再迭代"好看"，用快照测试守住回归。
2. **二胡音色**：合成器永远不如采样。对策：从一开始就把音源做成可插拔接口，合成器只是默认实现。
3. **规范漂移**：等《音乐简谱记谱规范》国标正式发布，可能要改符号。对策：AST 与渲染分离，改渲染层不动解析层。
