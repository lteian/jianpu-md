# 05 · 所见即所得编辑

> 目标：在工作台里点住一个音就能改谱，像五线谱软件那样。约束：改完还是**纯文本**，用户手写的东西（注释、歌词、圆滑线括号、间距习惯）不能被一次点击冲掉。

## 一、为什么不是"改 AST 再整体序列化"

省事的做法是 `parse` → 改对象 → `JSON.stringify` 回文本。但那样会：

- 丢注释（`% 第一段`）、空行、front matter 里你自己写的键
- 丢手写间距（`(6.5)(45)6` 变成别的样子）
- 圆滑线、房子、反复记号全靠 token 顺序表达，重排一次就可能变意思

所以走**源码定点改写**：把"改音高 / 改时值 / 改八度 / 改附点 / 删音 / 插音 / 连弓"翻译成对**某一行某个 token** 的替换，其它字符一个不动。

代价明说：**被改到的那一行**会按规范间距重排空格（`(3 5)` → `( 3 5 )`），语义等价，渲染不变。

## 二、`note.idx` 与 token 下标不是一回事

`layout` 里的音带 `idx`（全局音序号），但源码行里一个"音"可能占多个 token（`(`、`)`、倚音、`{DunYin}` 技法名都占 token）。**不能靠 idx 反推 token 下标**。

解法：`parseMusicLine(text, line, rec?)` 多接一个 `rec: NoteTokenRef[]`，把 `{ ti, note }` 记下来。于是：

```ts
const spans = locateNotes(src);       // Map<idx, { line, ti, note }>
```

坑：`parse()` 里的 `seq` 是模块级计数器，**对单行再解析一次会接着编号**，拿到的 idx 和 layout 里差一大截。所以 `locateNotes()` 先 `resetNoteSeq()`，再按**同样的行序**重放一遍——重放是确定性的，idx 与 `parse()` 逐个吻合（倚音也走 `parseNoteToken`，同样吃序号，重放时数量一致）。

## 三、简谱没有纵向音高轴

这是设计上必须承认的物理事实：五线谱上一个音往上挪就是音高变高，简谱里 `1` 和 `5` 都写在同一水平线上，**音符在页面上没有可移动的第二维**。

所以拖动映射成：

| 手势 | 含义 |
|---|---|
| 左右拖 | 时值（右 = 变长，左 = 变短），走 `全 / 二分 / 四分 / 八分 / 十六分 / 三十二分` 六档 |
| 上下拖 | 音级（上 = 数字变大，1–7 封顶） |
| Shift + 上下拖 | 八度（加 / 去一个八度点，±3 封顶） |

手感参数：音级 / 时值一档 ≈ `noteSize × 1.7 ≈ 32px`；八度一档 ≈ `×2.4 ≈ 76px`（八度最多三个点，太灵敏会一下拖到底）。手势在位移超过 8px 时**锁定主轴**，避免斜着拖时音级和时值一起变。

## 四、拖动是实时的，不是松手才生效

- 整个编排一次编译只要 **5–10ms**（50 小节全曲），60fps 拖动完全扛得住
- 每次 `mousemove` 算"目标绝对值"（`{kind:'dur', level}` / `{kind:'digit', digit}` / `{kind:'oct', delta}`），**幂等**，所以反复重放不会累积漂移
- 拖动期间不压撤销栈，**一个手势只留一个还原点**（按下时快照）

## 五、连弓不只是插两个字符

圆滑线在语法里是独立的 `(` `)` token，所以取消连弓不能只删音符 token 里的字符。两个必须处理的边界：

1. **选中已有连弓里的音再点"连弓"要能去掉它** → 把紧贴在选区外侧的 `(` / `)` 并入选区一起删除
2. **括号要和"是哪个音"对齐** → 删除后再按"非括号 token 计数"定位插入点。这里用错基准（用并入选区后的下标）会插到前一个音前面，表现为 `( 3 ( 5 ) …`——离正确只差一个 off-by-one

配对扫描用栈：只删**两端都落在选区内**的括号对；跨界的那一对原样留着，宁可不动也不要把别人的圆滑线拆坏。

## 六、API

```ts
import { locateNotes, applyNoteEdits, setSlur, serializeToken, durLevel } from 'jianpu-md';

const spans = locateNotes(src);                   // Map<idx, NoteSpan>

// 一批编辑，同一行的会合并、按下标倒序执行（插入/删除不漂移）
applyNoteEdits(src, [
  { idx: 3, op: { kind: 'digit', digit: 6 } },
  { idx: 4, op: { kind: 'dur', level: 3 } },      // 八分
  { idx: 5, op: { kind: 'oct', delta: 1 } },
  { idx: 6, op: { kind: 'dots', delta: 1 } },
  { idx: 7, op: { kind: 'acc', acc: 1 } },
  { idx: 8, op: { kind: 'dashes', delta: 1 } },
  { idx: 9, op: { kind: 'digitStep', delta: 1 } },
  { idx: 10, op: { kind: 'insertAfter', digit: 2 } },
  { idx: 11, op: { kind: 'delete' } },
]);

setSlur(src, 3, 7, true);                         // 幂等
serializeToken(note);                             // Note → '1\'-.'；parseNoteToken 的逆运算
```

测试在 `test/edit.test.mjs`（7 条）：序列化互逆、各操作、连弓幂等、多操作同行、编辑后仍可编译、整曲示例只改动被编辑的行。

## 七、保存

工作台里的改动先落在 `<textarea>`，再走两条路：

1. **写回文件**：`tools/serve.py` 提供 `POST /api/save`，只允许写 `examples/`、`scores/` 下的
   `.md` / `.txt`，路径里带 `..` 一律拒绝。`Ctrl+S` 写回当前文件，`Ctrl+Shift+S` 另存为。
   `GET /api/files` 给「打开」按钮列目录，`GET /api/ping` 让前端自己判断有没有这层能力。
2. **浏览器兜底**：没有 `/api/`（换成别的静态服务器）就退回 File System Access API；
   再不行就下载 `.md`。三层都不通也不至于丢内容。

另外每次渲染都把内容写进 `localStorage`（350ms 防抖）。重开页面时如果发现有草稿就自动恢复，
并在右下角提示——**这条路径和文件有没有保存成功无关**，断网、崩浏览器都能捡回来。

## 八、两个渲染坑（都不是排版问题）

1. `dotsOf()` 返回字符串，调用处必须 `g.push(...)`。曾经漏了 push，于是**八度点从来没有输出过**：
   谱面上 `1'` 和 `1` 长得一模一样。因为示例谱里恰好没有八度音，一直没暴露。
2. 弓法记号原本用字形 `ㄇ` / `∨`（U+3107 注音符号），缺这个字的字体会渲染成空白或豆腐块。
   二胡谱最要紧的记号不能赌字体，改成 `<path>` 画：拉弓 ∏、推弓 ∨。

还有一处 CSS 陷阱：`#pages` 是 column flex，整页 SVG 比容器高时会被 `flex-shrink` 压扁
（实测 1123px 被压到 746px，等比缩到 66%，八度点只剩 2.5px）。`#pages svg.page { flex: none }` 解决。

## 九、自动分节（敲音符时）

`autoBarLine(line, beatsPerBar)`（`src/edit.ts`）把一行按拍号重新插小节线：

- 行内普通 `|` 全部丢掉，按音符累计拍数重插；`|:` `:|` `||` `|]` 带语义，原样保留并断开累计
- 满一小节插一条；插的时候如果正处在 `( … )` 括号里，就等到 `)` 之后（不然线会插到连音中间）
- 后面紧跟着 `:|` `||` `|]` 时不补线（那是收尾线）
- 行首不是结构线、也不是行内拍号，就补一条 `|`；行末没落满也补
- `1 - 2` 里那条孤立的 `-` 是增时线，先并回前一个音（`1-`）

前端（`web/app.js` 的 `autoBarAtCursor`）只对**光标所在行**动手，并且：

1. 行首必须是 `|` `:` `(` `[` 或数字 —— 否则 `title: 1`、`## 第 1 课` 都会被当成音符重排
2. 用 `tokenize(before)` 数「光标前经过几个音」来还原光标，不能按空格切
   （`12` 是一个 token、两个音，这个坑实测把顺序都打乱了）
3. 替换整行用 `setRangeText`(preserve)，不用 `value =`，尽量保住浏览器的撤销栈
4. `inputType === 'insertFromPaste'` 直接跳过，粘贴进来的谱不该被改

可视化那边（`web/editor.js` 的 `edit()`）按 `op.kind` 决定要不要重排：
`dur` / `dashes` / `dots` / `slash` / `delete` / `insertAfter` 会改总拍数 → 重排；
改音级、八度、记号不动分节。

## 十、多小节休止（`R18`）

分谱的现实：一首四分钟合奏曲，二胡声部有大半时间在数拍子。
逐个写空小节（`| | | |`）既占版面又要写十几行，而且每一条都触发「空小节」告警。

所以 `R18` 不是「一个没有音符的小节」，而是**一个吃掉 18 个小节号的占位行**：

```ts
// parser.ts，编号阶段
for (const m of it.measures) {
  if (m.restBars) { m.no = counter + 1; counter += m.restBars; continue; }
  if (m.no > 0) counter = m.no;
  else m.no = ++counter;
}
```

三个连带约束：

1. **必须独占一行**（`layout.ts` 的 `toRows`）——它没有音符，算不出自然宽度，
   混在乐谱行里会让 `measureWidth` 和换行逻辑一起失准。
2. **`validate` 要提前 return**，否则报「空小节」和「拍数为 0」。
3. **渲染走独立分支**（`renderRestBars`），不进 `renderSystem` 的小节循环 ——
   那里的每一行都在假设 `measure.notes` 非空。

行高给 `max(34, systemHNoLyric * 0.52)`：比正常行矮一半，读者一眼能看出这不是乐谱行。

## 十一、行距（`spacing`）

行高不是常量：`systemH`(96) / `systemHNoLyric`(76) 只是「默认」，实际按
frontmatter 的 `spacing` 缩放：

```ts
const gap = lineGapOf(doc);   // 0.5–1.8
const systemHeight = (hasLyrics) => Math.max(hasLyrics ? 80 : 67, base * gap);
```

**硬底不能省**。压过头会出的事故不是「丑」，是**低音点撞到下一行的减时线**：

- 音符基线在 `noteBaseline`(40)，往下还有减时线 + 最多 3 个低音点（约 24px）→ 67
- 有歌词再加一行（`lyricSize` 16，画在 `y+30`）→ 80

`0.93` 一档约等于「一行省 5px」，一页 14 行能省 70px —— 刚好是「多出一行」的量级。

工作台的「压一页」不是猜的：二分搜索 `[60, 100]` 区间里**还能停在一页的最大百分比**，
取到就写回 frontmatter。之所以取最大而不是最小，是因为行距越接近 100 越好看，
刚好塞进去就够。

另外 `setMeta` 允许传空值 = 删除该键：行距调回 100% 时不该在 frontmatter 里留一行 `spacing: `。

## 十二、谱面光标（键盘打谱）

简谱打谱的真正手感是「光标在音之间移动，敲数字就落一个音」，
而不是「选中音符再改属性」。所以编辑器里加了一套**光标模式**：

- 光标 = `{ line, k }`：第 `line` 行、第 `k` 个音**之前**。不是选区，所以能停在两个音中间
- 谱面上画一根红色竖线（`g.caret`），每次重排后按新的坐标重画
- `←` `→` 移一个音，到行首/行尾自动跨到上一行/下一行；`↑` `↓` 换行；`Home` `End` 行首行尾
- 点谱面空白处进光标模式（同时清掉选区），`Shift+拖` 才是框选

### 关键：光标要的是**字符位置**，不是 token 下标

`tokenize` 不能用来定位：`|(6.5)(45)6|` 这种会被拆散、引号里的空格会被替换、
JPW 的 `{DunYin}` 会被改写 —— 位置全对不上原文。

所以另写了 `scanLineNotes(line)`（`src/parser.ts`）：逐字符扫出每个音在**原文**里的
`[start, end)`，规则必须和 `parseMusicLine` 对齐（音的顺序一致）：

- 结构符 `| : ( ) [ ] ^ _` 跳过，引号文字整段跳过
- `2/4` 这种行内拍号不是音（斜杠后紧跟数字就判为拍号）
- `1'` `b7` `1//` `1..` `5@la` 都算**一个**音

插入时用字符位置往源码里插文本，其它内容一个字节都不动 ——
引号文字、行内拍号都不会被改坏。

### 与「自动分节」的关系

插入后立刻 `rebarLines(那一行)`：满拍自动落小节线，用户不用自己敲 `|`。
但手动插的小节线（`\` 键）**不**重排 —— 自动分节会把手插的线按拍数重插掉，
用户想自己控制小节线时得听他的。

### 快捷键顺序有坑

`Ctrl+↑`（音阶）和 `Alt+←`（插低音）必须排在「方向键移动光标」**前面**，
否则会被当成普通方向键吃掉。这个坑踩过一次：按了没反应，以为功能没实现。

### 左右键只能有一套含义

第一版把左右键做成了「有选区就改时值、没选区就移光标」。问题很明显：
**点一下谱面里的音就会产生选区**，于是同一个按键忽然变成另一个功能，
用户会以为程序有毛病（当场就有人问「左右键怎么变成改音长的了」）。

现在左右键**永远**是移动光标，并且一按就退出选中模式。
改音长挪到 `Ctrl+←` `Ctrl+→`，另外还有拖动和 `-` / `Shift+-` 两条路。

方向键表达的是「我在哪儿」，属性修改是另一类动作 —— 两者不要共用键。

## 十三、源码栏默认藏起来

打谱时真正需要的是「谱面 + 光标」，源码是偶尔才碰的。所以左栏默认收起，
`#wrap` 的 grid 从 `minmax(320px, 34%) 1fr` 变成 `0 1fr`（加 `src-hidden` 类）。

两个连带处理：

1. **告警要挪走**。原来 `#diag` 在左栏里，藏起源码就看不见告警了 ——
   「第 31 小节拍数不对」这种提示不能因为面板折叠就消失。
   把它移到 `<header>` 下面做成横向告警条，折叠时照样在。
2. **焦点不能留在隐藏的 textarea 里**。`editor.onKey` 会跳过 `INPUT/TEXTAREA`，
   焦点若还在隐藏的 textarea 上，打谱快捷键会全部失灵。收起时必须 `blur()`。

源码栏折叠时想改曲名怎么办：**双击谱面上的曲名 / 页眉信息**，
源码栏展开并把光标定位到 frontmatter 对应那行（`data-key="title|subtitle|info"`）。

## 十四、两套版式（默认 / JPWORD）

源码栏收起之后左边空出来一大块。与其留白，不如照 JP-Word 的样子重排一版，
做成**可切换的版式**（顶栏下拉 / 菜单「视图 → 版式」，偏好记在 localStorage）。

做法是**同一套 DOM，两套 CSS**：`body.layout-jpw` 打开后：

| 元素 | 默认版式 | JPWORD 版式 |
|---|---|---|
| `#bar` | 顶栏一排控件 | 隐藏（功能进了菜单） |
| `#menubar` | 隐藏 | 显示：文件/编辑/视图/插入/格式/工具 + 右侧快速按钮 |
| `#tools` | 横向一条 | 左侧 92px 竖排浮动工具窗 |
| `#status` | 隐藏 | 显示：曲名/光标/时值/选区/页数/缩放 |
| `#wrap` | `minmax(320px,34%) 1fr` | `92px 1fr`（源码栏展开时三栏） |

菜单用**配置表**渲染（`MENUS()` 返回 `[名字, 快捷键, 动作]` 的数组），
不写一堆重复的 DOM 代码；每项统一 catch 异常，失败给 toast 而不是静默。

两个容易漏的点：

1. 竖排工具窗里的按钮组要从 `flex-direction: row` 改成 `column`，
   组与组之间的分隔线也要从「右边框」改成「下边框」。
2. 切版式会改变谱面可用宽度，`applyZoom()` 要在切换后**重算一次**，
   否则整页 SVG 会按旧宽度缩放，看起来没变化。

### 坑：grid 的列是按子元素**顺序**分的，藏一个就全乱

源码栏用 `display: none` 藏起来之后，grid 里**少了一个盒子**，
后面的元素会**往前挪一格**：

```css
#wrap { grid-template-columns: 0 1fr; }        /* 源码那列宽 0 */
#wrap.src-hidden #left { display: none; }      /* ← 谱面掉进第 1 列（宽 0） */
```

结果就是「一关源码，谱面整页都没了」—— 谱面掉进了 0 宽的那一列。

解法不是去算列宽，而是**改用 `grid-template-areas` 按名字定位**：

```css
#wrap {
  grid-template-columns: minmax(320px, 34%) 1fr;
  grid-template-rows: auto 1fr;
  grid-template-areas:
    "tools tools"
    "left  pages";
}
#tools { grid-area: tools; }
#left  { grid-area: left; }
#pages { grid-area: pages; }
```

有了 areas，元素归哪个格子跟它在 DOM 里的位置无关，
`display: none` 掉一个也只是空出一块区域，别的元素不会挪位。

顺带把 `#tools` 移进了 `#wrap`（原来是 `#wrap` 的兄弟节点），
JPWORD 版式要把它竖着放在最左边做浮动工具窗，在同一个 grid 里才排得出来。
